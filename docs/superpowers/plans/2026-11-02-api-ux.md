# hockey-model API UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This repo does not use subagent-driven development; work inline.

**Goal:** Build the caller-facing Python API for players, rosters, team projections, matchups, and playoff odds, with a thin CLI wrapper.

**Architecture:** Typed value objects in `hockey_model.types`. Identity resolution and roster validation are pure functions over those objects. Modeling sits behind three protocols (`StatModel`, `JointModel`, `StandingsModel`) that the data-source work fills in later. The CLI calls the same functions and prints JSON.

**Tech Stack:** Python 3.14, uv, pytest, hypothesis, ruff, ty. No runtime dependencies beyond the standard library in this plan.

**Spec:** `docs/superpowers/specs/2026-11-02-api-ux-design.md`

## Global Constraints

- Python 3.14, managed with `uv`. Run every tool as `uv run ...`.
- Functions at most 100 lines and cyclomatic complexity 8.
- Functions take at most 5 positional parameters.
- Lines at most 100 characters.
- Absolute imports only (`from hockey_model.types import Player`).
- Public APIs have docstrings.
- Name search ignores case and accents, and does not match nicknames.
- The default interval level is `0.8`.
- The default horizon is `1` game.
- Rate stats are never summed. A team-level rate stat raises `RateStatAggregationError`.
- Matchup win probabilities sum to `1.0`, with overtime and shootout wins going to the side that takes them.
- A starter in a slot with no projection raises `MissingProjectionError`. A bench player with no projection is excluded and does not raise.

## Review Focus

1. A name that matches an active and a retired player must raise `AmbiguousPlayerError`, not pick one. Owned by Task 2.
2. A name with accents (for example "Zdeno Chára") must match its unaccented form. Owned by Task 2.
3. An empty roster must return a zero total with an empty breakdown, not an error. Owned by Task 5.
4. A projection with a non-finite point or bound (NaN, inf) must raise `ValueError` at construction. Owned by Task 3.
5. A matchup whose model returns win probabilities that do not sum to `1.0` must raise, not return a skewed pair. Owned by Task 6.

- Create: `src/hockey_model/types.py`: `Player`, `Team`, `Standing`, `Roster`, `Slot`, `Projection`, error classes. One responsibility: value objects and their validation.

- Create: `src/hockey_model/models.py`: the three protocols and the in-memory fakes used by tests.
